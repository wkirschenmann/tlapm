Scaling tlapm: 19 pull requests, from bugfixes upward

A branch off main containing nothing but code, one subject per pull request, ordered so that the bugfixes come first and every optimization arrives with its own before/after measurement on a stock binary.

What this asks for

Review in the order below. The first five commits are bugfixes and carry no performance argument: they repair behaviour tlapm already advertises. Everything after them is an optimization with a measured effect, a validation recipe that runs on a stock build, and — where relevant — an existing switch to turn it off.

Nothing here adds a command-line flag, an environment variable, or a measurement probe. The development instrumentation we used exists on a separate branch and is deliberately not part of this proposal: adopting an optimization must not require adopting a probe.

01

It is a scale problem

Nothing here is a general slowdown, and that matters for how the diffs should be read: on small and medium proofs tlapm is already fast, and the changes below must be — and are — neutral there. The cost appears when contexts get large, which is what deep INSTANCE hierarchies and long single-module proofs produce.

Two shapes of pain, both reported from real use rather than constructed:

throughput

A whole module stops finishing

A 30 000-line single-module proof (29 965 obligations) is provable in slices of ~2 000 lines, five slices of two minutes each — but a single pass did not terminate: live memory grew with the obligation count until the heap gave out.

before: out of memory at ~26 000 of 30 000 obligations, after 110 minutes

latency

The editor loop stalls

In the language server, each interaction re-parses, re-elaborates and re-fingerprints the whole file and its dependencies — twice, since the server and the child tlapm both do it. The cost is dominated by terms that grow with the file, not with the edit.

before: keystroke → diagnostics 59.7 s on that module

Where this branch leaves it. Same machine, same module: the single pass completes in 285 s at a flat 1.5 GB. The editor's quadratic step/obligation association is gone, which takes the keystroke to 11.5 s; the rest of the editor work is not in this proposal (see §7). On the small and medium synthetic proofs, every measurement is within noise of main — §4.

03

The mechanism the throughput items exploit

Consecutive obligations of a module share almost their whole context: the module scope, then each theorem statement appended to the ones before it. On the 30k module the median context is 743 hypotheses, of which 699 are the physically same objects as in the previous obligation — a median divergent tail of one hypothesis. Expansion, normalization and constness annotation nevertheless recomputed the whole context per obligation.

All three passes visit hypotheses front to back with a state that only grows, so the state after position i is a pure function of hypotheses 0…i−1. Cache it per position, compare the previous obligation's hypothesis array with ==, and restart the fold at the first divergence. Physical equality is what makes stale hits impossible: anything rebuilt or from another module compares unshared and falls back to a full fold.

The same observation bounds what else is worth trying: the dead weight in those contexts is free because it is shared. 85 % of every context is dropped by prune_context before encoding, and pruning it earlier — before the expensive passes — rebuilds each context, destroys that sharing and costs ×3.2 to ×4.4 in wall time. Measured, not assumed; it is not in this proposal.

04

Test cases and method

Everything in §5 is measured on the public synthetic family so that any reviewer can reproduce it without our corpora: a generator parameterised by lemma count, steps per lemma, hidden definitions and citations per BY DEF. Named lemmas become visible context definitions carrying their statement, which is what reproduces the growth term real proofs have. Two private specifications — an INSTANCE-heavy refinement chain (9 967 obligations) and a single-module 30 000-line proof (29 965 obligations) — are used only where a figure is quoted for the large end; no specification content appears here.

What is run, and what is not

Two metrics, both from stock flags on a stock build, no probes, no patched binary:

  • latency floor — tlapm -N --nofp MODULE.tla: parse, elaborate, generate obligations, stop. This is the floor of every editor interaction and the per-worker fixed cost of any parallel scheme.
  • preparation throughput — tlapm --noproving --nofp MODULE.tla: the whole per-obligation pipeline with no prover launched, so the number is reproducible and prover-independent. Peak resident memory comes from the same run.

Wall clock is the figure to argue on. The --timing phase table is useful for attribution and is quoted as such, but it is indicative: it is repaired by the first bugfix below, and on main three of its rows are structurally zero and nested regions are misattributed.

Noise. One run per point, and main measured at both ends of the campaign: 2 588 ms / 51.7 s at the start against 2 153 ms / 50.4 s at the end. Preparation is stable to 2.5 % across the campaign; the latency floor is not, because the first run of a campaign meets a cold page cache, and the 17 % gap between the two main runs on that metric is the honest uncertainty on it. Every point is a single run taken immediately after its own build, and the whole campaign is one boot of one container — a restart invalidates comparison, so the sweep stamps every row with the boot it was measured on. Only steps larger than that floor are individually meaningful; the others say so in §6 and are argued on the mechanism.

Correctness gates, per change

Every commit is checked with both suites — dune runtest src and dune runtest lsp, the latter 23 of 23 — and against the test/fast suite run with the full prover stack: Z3 4.8.9, Zenon, and Isabelle 2025 with the TLA+ heap built from this repository’s own isabelle/ sources. 47 of 48 pass, and the gate is that the fail-set is identical to main’s. The single failure is fast/fingerprint/FingerprintVariablesParameters_test.tla: it expects 1 of 2 obligations to fail and gets 2 of 2, because Z3 4.8.9 does not prove \E y : y # x here. It fails the same way on main, so it is a property of the prover versions in this environment, not of any change proposed here.

The stack is worth installing before reviewing this branch: the download is pinned by SHA-256 in deps/isabelle/dune.mk, and the TLA+ heap builds in about half a minute on four cores. Without Isabelle the same suite reports 40 of 48, and the fail-set is still identical to main’s — the gate holds either way, but seven of the failures are the missing backend rather than anything this branch does.

For output-preserving changes, the obligation stream is compared before and after:

tlapm -N --toolbox 0 0 --printallobs --nofp MODULE.tla 2>&1 \
  | grep -vE '^@!!(time-used|id):' > arm.txt
diff arm-before.txt arm-after.txt          # must be empty

For the two changes that remove hypotheses, that stream is not sufficient — it prints the obligation after expansion and normalisation but before prune_context. What the provers receive is the solver input files, which --debug tempfiles keeps and each of which opens with the shipped sequent and a ;; Generated from file …, line N, characters a-b key. Rename by that key, then:

diff -ru before/ after/                    # what changed, per obligation
diff -ru before/ after/ | grep '^+[^+]'    # must be empty  ==  subset

On the pre/post-prune pair that check yields 4 200 deleted lines and 0 added. It needs a real prover run: --noproving writes no solver files.

06

The pull requests, commit by commit

Nineteen pull requests, twenty-six commits. Each block states why the change exists, then per commit: what it changes, the correctness gate that applies to it, the switch that turns it off where there is one, and the measured effect of that commit alone — the point before it against the point at it, on the two synthetic sizes and on both private specifications. Every commit message on the branch carries the same gate text, so a reviewer reading git log sees it without this page.

Reading the measurement tables. gen is tlapm -N --nofp — parse, elaborate, generate. prep is tlapm --noproving --nofp — the whole per-obligation pipeline, no prover. peak is the maximum resident set of the prep run. One run per cell, so ratios under about 1.1 are noise and are labelled as such in the commit's own text; the tables are there so that no commit can hide behind a group total. A cell reading > 900 s is a run stopped at the fifteen-minute ceiling.

Which of these are carried by a measurement, and which are not

Computed from the campaign, not asserted. For each pull request: the largest improvement it produces on any corpus and any of the four metrics in §5, and whether it is the commit at which a run that did not finish starts finishing. One noisy metric on one corpus is not allowed to promote a change — an effect counts either because it is large on its own (×1.35 or more) or because it repeats on a second corpus. Everything else is listed as argued on its mechanism, because that is what it is: this campaign cannot separate it from zero.

The five bugfixes are not in this table. Two of them do speed things up, but none is an optimization and the decision to take them is of a different kind — that is why they are item #0.

The work was done with Claude Code. Every design decision, every measurement protocol and every rejection in §7 was reviewed by a human; the numbers were produced by running the code, not by a model.

After expansion, an obligation's context still carries every hidden definition and every instantiated theorem statement in scope, whether or not the goal can reach them. These are the two commits on the branch that change what the provers receive — everything else is byte-identical.

dc37462 backend/prep: prune hidden definitions unreachable from the goal Fable 5

1 file, +75/−0 src/backend/prep.ml +75/−0

changes A marking pass from the goal and the facts computes the transitive reachable set over the context; only unreferenced hidden operator and pragma definitions are dropped, and their slots are replaced by Opaque "__pruned__", so a reachability mistake fails loudly at encoding time instead of silently changing a verdict. Declarations, recursive and instance definitions and every fact are kept; an un-analysable hypothesis conservatively keeps all its predecessors. Placement matters twice over: it runs after expansion, normalisation and the triviality check — which can discharge a support obligation from a hidden fact equal to the goal — and only on the backend path, so an obligation that never reaches a prover never pays for it. Deliberately not in this proposal

measured null

Lazy obligation generation

Full correctness parity, no performance or memory change: contexts share their prefixes structurally, so holding 30 000 sequents was already nearly free.

measured worse

Pruning before expanding

×3.2 to ×4.4 slower and more memory, for the reason in §3.

unsound

Fingerprints blind to declaration names

Merges 369 classes on the 30k module, three of which have differing shipped forms — one obligation's result would answer for a different problem.

needs prior work

The incremental editor modes

Scoped re-elaboration and a forked in-process prover take the keystroke to 2.0 s and a step verdict to 0.4–1.0 s, but they leave inner expression positions of reused units stale by design, which the proof-decomposition code actions consume. The position shifting has to land first.

separate feature

Chunked parallel proving

Proving contiguous ranges in parallel worker processes is ×2.24 on the 30k module with identical verdicts, but it is a new command-line surface rather than an optimization of the existing path, so it belongs in its own proposal.

design input

INSTANCE × EXTENDS deduplication

20.5 % of context definitions on the INSTANCE-heavy corpus are instantiated copies of directly-extended ones. Elaboration is 1.0 % of that run, so the ceiling is 1 %, and the copies sit in the shared prefix that costs nothing.
