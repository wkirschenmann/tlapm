# A nested-INSTANCE refinement stack, small enough to read

This corpus exists because `INSTANCE` does not share — it **copies** — and the
copies are most of what an obligation carries. Everything here is a few dozen
lines, everything is public, and every number the proposal document quotes
about it can be re-run from this directory.

## The stack

```
        FiniteSets, Naturals, Sequences        (standard, EXTENDed once)
                    ↓ EXTENDS
L0State ─ parameters, state, standing ASSUMEs
    ↓ EXTENDS
L0 ─────── the specification and eight named properties
    ↓ EXTENDS
L0Theorems ─ the citable interface: what holds, proofs elsewhere
                    ↓ ↓ ↓
L1State ─ level 0's declarations by EXTENDS, plus its own
    ↓ EXTENDS
L1 ─────── L0 == INSTANCE L0Theorems, and eight compositional properties
    ↓ EXTENDS
L1Theorems ─ level 1's citable interface
                    ↓ ↓ ↓
L2 ─────── L1 == INSTANCE L1Theorems, and nothing else
    ↓ EXTENDS
L2Proofs ─ the level-2 proof: 40 lemmas, four and five levels deep
```

Two levels of `INSTANCE`, so level 2 sees level 0 twice: once as `L1!L0!X`,
inside the copy of level 1, and never any other way. `EXTENDS` never renames;
`INSTANCE` always does. **The prefix counts `INSTANCE` hops, not `EXTENDS`
hops** — that single sentence is what `CiteTrap.tla` is about.

The theorems modules declare their results without proving them. That is how a
refinement stack separates a citable interface from a proof module, and it is
what makes citation, rather than discharge, the subject here.

## The three things to run

Everything below assumes `tlapm` on `PATH` and the standard library reachable;
add `-I <path-to>/library` if it is not.

### 1. What one `INSTANCE` copies in

```
tlapm --noproving --nofp Ladder1.tla        # …through Ladder4
```

`Ladder`*n* instantiates `L1Theorems` *n* times and has exactly one
obligation, so the size of that obligation's context is a direct reading of
what one `INSTANCE` brings. It is linear: **143 definitions and 165 hypotheses
per `INSTANCE`**, and 71 of those 143 — half — are the copy of level 0 that
arrived two renamings deep.

Reading the breakdown needs the `TLAPM_TRACE_DEFS` probe, which lives on the
documentation branch rather than on the proposal branch:

```
TLAPM_TRACE_DEFS="J1!,J1!L0!" tlapm --noproving --nofp Ladder1.tla
```

The `Ladder` files are **generated** by `../harness/instance_demo.sh`. Do not
edit them: they name level 1's theorems, and a rename at level 1 breaks them
in a way tlapm reports badly (see *Two traps* below).

### 2. What the copies cost a proof that uses them

```
tlapm --toolbox 0 0 --threads 4 L2Proofs.tla
```

3,239 lines, 2,703 obligations, **all of them proved** with the stock backends.
Two kinds of lemma, because they stress different things:

- a **`Cite`** lemma keeps every operator opaque and chains instantiated
  theorems — what it exercises is the context, which carries every definition
  of both levels below whether or not the goal mentions it;
- an **`Open`** lemma names definitions in `DEF`, so the *bodies* of the
  invariants really enter the obligation. That is what a proof does when it
  opens an invariant to reach one conjunct, and the only way a definition's
  weight reaches a prover at all.

Both run four or five levels deep. Depth is not decoration: tlapm emits one
obligation per leaf, and every step's statement joins the context of its later
siblings and of everything nested beneath it, so a tree of depth five costs
quite differently from the same leaves laid out flat.

`L2Proofs.tla` is generated by `../harness/gen_l2proofs.py` from the lemma
index, with no randomness — regenerating it is byte-identical, and a diff means
the generator changed.

**What it costs.** On the base commit of the proposal branch, preparing this
file takes about **80 s and 1.6 GB**; at the tip, **5.4 s and 60 MB**. The
generated obligation stream is byte-identical between the two. A 3,239-line
proof over a stack whose own source is 264 lines makes tlapm walk **999,558
context entries**, 369 per obligation.

### 3. The naming trap

```
tlapm --toolbox 0 0 --threads 4 CiteTrap.tla
```

**This module is expected to report one failed obligation.** `CitesWrong`
failing is the demonstration; a fully green run would mean the corpus had
stopped showing anything. It is deliberately outside what
`../harness/instance_demo.sh` gates — that gate covers `L2Proofs.tla`, which
must be entirely green.

There is exactly one `IsFiniteSet` in these sources, the standard one,
`EXTENDS`ed once at the bottom. Level 2 nonetheless sees three symbols with
that body and no way to tell them apart by eye:

| symbol | reached by |
|---|---|
| `IsFiniteSet` | `EXTENDS` — no prefix |
| `L1!IsFiniteSet` | one `INSTANCE` hop |
| `L1!L0!IsFiniteSet` | two |

`L1Theorems` states its assumptions with the unprefixed one, so one hop later
they read `L1!IsFiniteSet`. Naming the two-hop copy instead is well formed,
means the same thing, and does not match. `CiteTrap` shows the failing
citation, the fixed one, and the escape hatch — unfolding both copies with
`DEF` so the prover bridges them itself, which works and costs, because the two
definitions then enter the obligation expanded.

## Two traps worth knowing before you edit anything

**An instance-qualified name that does not exist gives no diagnostic.**
`I!Nonexistent` where `I == INSTANCE A` makes tlapm abort with a bare
`Failure("Expr.Anon: 1EMPTY")` — no locus, no name — where a plain unknown name
at least prints `Operator "Nonexistent" not found` first. If a rename here ever
produces that message, look for a stale `X!Y` reference.

**A comment block whose lines are not individually closed swallows the file.**
`(*` nests in TLA+, so a block of `(*`-prefixed lines with one closing `*)`
leaves the lexer inside a comment and tlapm aborts with
`Failure("lexing: empty token")`. Every generated file here closes each comment
line on its own.

## Regenerating the numbers

```
TLAPM=<probe-carrying binary> \
TLAPM_MAIN=<binary built from the base commit> \
TLAPM_TIP=<binary built from the branch tip> \
  ../harness/instance_demo.sh
```

It writes `../instance_demo.csv`, which is where the proposal document reads
every count and timing it quotes about this corpus. It refuses to write that
file if any obligation of `L2Proofs.tla` fails, or if the two obligation
streams are not byte-identical — a document should not be able to claim a green
corpus that is not, and the script is the thing that stops it.

Three binaries, because which one produced what matters: counts come from the
probe-carrying one and are a property of the corpus rather than of a version;
timings come from the two ends of the series, A/B interleaved, medians. The
script will not run with fewer, and says why.

Run it on an idle machine. The counts are deterministic; the timings are not.
